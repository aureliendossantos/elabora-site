Le plan, c’est le contrat avec votre client : le but du module, son public, ses objectifs, ses parties et leurs points, et les textes ou les questions que le client veut voir tels quels. Votre IA l’écrit et le réécrit ; vous en faites des versions (V1, V2…), vous les envoyez au client, et vous notez celle qu’il a validée.

## Lire le plan

Ouvrez la vue **Plan**. Trois façons de le lire, en haut à gauche :

- **Sommaire** : les parties et leurs points, une ligne chacun, qui s’ouvrent sur place. **Tout déplier** et **Tout replier** les ouvrent tous d’un coup.
- **Cartes** : une colonne de cartes par partie, pratique pour réorganiser.
- **Document** : le plan tel que votre client le lira, comme il sera exporté.

Le plan dit aussi ce qui manque : un point qu’aucun écran ne couvre, un objectif ni exercé ni évalué, une suite d’écrans sans activité. Pour chercher un mot, ⌘F ou la loupe : **Rechercher dans le plan** ; **Dans tout le module** cherche aussi dans les écrans.

## Modifier le plan

Cliquez sur un point : il se modifie dans **Propriétés** (**Titre**, **Nature**, **Partie**, **Sources**, **Description**, ses textes validés, sa voix off). Pour réorganiser, glissez un point ou une partie, ou utilisez ⌥↑ et ⌥↓ : les écrans qui le couvrent suivent.

Le plus souvent, vous le demanderez à votre IA :

> Ajoute une partie sur les erreurs fréquentes avant l’évaluation finale, avec un objectif et deux points.

## Le brouillon écrit par votre IA

Quand votre IA écrit le premier plan, elle dit en tête ce qu’elle a décidé seule (« Ce que Claude a décidé ») et, s’il le faut, pose une question, une seule. Changez une décision depuis son menu (ou **Autre chose…** pour l’écrire vous-même), répondez à la question avec **Répondre…** : votre réponse part à l’IA, qui réécrit le plan. Ces décisions et cette question disparaissent quand une version est validée ; elles ne sont jamais montrées au client.

## Faire une version et l’envoyer

En tête du plan, une pastille dit où il en est : **Brouillon**, « V1 envoyée le 3 oct. », « V2 validée par … le 5 oct. », avec le nombre de modifications faites depuis. Un clic sur la pastille ouvre le panneau **Modifications** · **Versions**.

1. Dans **Versions**, **Créer la V1** fige le plan tel qu’il est. Vous continuez à le modifier ensuite : la V1, elle, ne bouge plus.
2. **Exporter**, dans la barre d’outils, propose **Word (.docx)…** (les modifications suivies, vos notes en commentaires) ou **PDF…** (les modifications marquées dans le texte).
3. L’export montre la dernière version. Si vous avez modifié le plan depuis, Elabora le dit et propose **Exporter la V1** tel quel, ou **Créer la V2 et exporter**. Il ne crée jamais une version sans vous.
4. Envoyez le fichier à votre client. Elabora note la date d’envoi sur la version.

## Noter la validation du client

Quand le client a dit oui, cliquez sur **Valider…** (en tête du plan, ou sur la version dans **Versions**). Dans **Valider une version du plan**, choisissez la version qu’il a lue, puis remplissez **Validée par**, **Le** et, si vous voulez, **Référence** (un e-mail, un bon de commande). Confirmez avec **Valider la V2** (ou la version choisie). Les modifications faites après cette version n’en font pas partie : elles restent marquées.

## Après la validation

Le plan reste modifiable, par vous comme par votre IA. Ce qui a changé depuis la version validée est marqué sur place (**Ajouté**, **Reformulé**, **Déplacé**, **Modifié**) et listé dans **Modifications**, où chaque changement propose **Revenir à la V1** et une **Note pour le client**, qui apparaîtra dans la marge du prochain document (en commentaire dans Word). La prochaine version montrera au client exactement ce qui a bougé.

Les textes validés **à l’identique** sont ceux que le client a approuvés mot pour mot. Pour en corriger un, **Déverrouiller**, modifiez, puis **Reverrouiller** ; il apparaît en orange, et le client le verra marqué dans la prochaine version. Votre IA, elle, ne peut pas les changer.

Sur les écrans, un texte qui vient du plan se reconnaît dans **Propriétés** : le reformuler sur le canevas change le plan, et Plan le marque jusqu’à la prochaine version. Un texte à l’identique, lui, ne se déverrouille que dans Plan.

Vous pouvez livrer un module dont le plan a changé depuis la validation : Elabora vous laisse faire et le signale dans les [vérifications](/fr/docs/apercu-et-verifications/). Pour revenir en arrière sur tout le module, et pas seulement sur le plan, voyez [l’historique](/fr/docs/bibliotheque/).
